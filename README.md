# shiftbook

本地多资源预约命令行工具。管理场地、设备、人员三类资源的开放区间，并在其之上创建、改期、取消预约与按日查询；支持按周重复的多资源**预约系列**、单次固定时段与弹性窗口的多资源**候补队列**（两种候补共用一条登记顺序）、场地维护、设备检修、人员休息等**资源临时停用**、批量改期的**操作记录与安全撤销**，以及本地 **iCalendar 文件导入**（UID 永久关联首次生成的预约，重复导入自动识别为重放）。

- TypeScript 编写，使用 Node.js 24 直接运行（类型擦除），**无外部运行依赖**。
- 数据保存在本地单个 JSON 文件中（默认 `shiftbook-data.json`，可用 `--data` 指定）。
- 时间为与机器时区无关的营业地时间：日期时间 `YYYY-MM-DDTHH:mm`，查询日期 `YYYY-MM-DD`，允许跨日。
- 区间左闭右开；开放区间重叠或相接视为连续开放；仅共同资源时间重叠才算冲突。

## 运行

```sh
node app.ts --help
```

## 测试

```sh
npm test
```

等价于 `node --test test/batch-ops.test.ts test/ical-import.test.ts test/batch-validate.test.ts`。使用 Node.js 24 内置测试运行器（`node:test`），无外部依赖、不访问网络、不读取默认数据文件。覆盖批量改期（混合提交、幂等）、安全撤销（整笔拒绝、恢复受阻、连续操作）、真实保存失败与重试、旧文件兼容及非法记录负例，以及 iCalendar 导入（新增与重放、混合文件、改期/取消后不复活、UID 不一致整批拒绝、开放不足与批内冲突报告、结构错误负例、跨日与年份边界、用法错误、损坏导入记录检测）；共用批次校验的回归覆盖整批交换成功与真实批内冲突双方报告、非标识顺序的多项失败按清单顺序报告、有效停用造成的覆盖不足（系列与撤销恢复）、改期或取消后重放预约按当前安排和状态参与占用、保存失败逐字节保留且标识未消费、无变化操作不写文件。每个场景在独立临时目录中经命令行入口操作，保存结果由新进程查询；任一断言失败即非零退出并标明场景，结束后自动清理临时文件。

## 命令

```sh
# 登记资源（--open 可重复，至少一个；类型可写 venue/equipment/person 或 场地/设备/人员）
node app.ts add-resource --type 场地 --name 一号会议室 \
  --open 2026-10-05T08:00/2026-10-05T12:00 \
  --open 2026-10-05T13:00/2026-10-06T20:00
node app.ts list-resources

# 创建预约（可同时指定多个不同资源；一次占用全部）
node app.ts create-booking --resource R0001 --resource R0002 \
  --start 2026-10-05T10:00 --end 2026-10-05T11:00

# 按周重复系列：首项起止时间 + 正整数次数（含首项）+ 至少一个已登记资源
# 自首项起，每项相对前一项将起止时间同时后移 7 个营业地日历日，
# 时刻与跨日长度不变，全部成员使用相同资源
node app.ts create-series --resource R0001 --resource R0002 \
  --start 2026-10-05T10:00 --end 2026-10-05T11:00 --count 4
# -> 返回系列标识 S0001 及按发生顺序关联的各成员预约标识 B0001..B0004

# 查询系列：全部成员、资源、时间与状态，按当前开始时间、预约标识排序
# （含单独改期或取消的成员）
node app.ts list-series

# 按日查询（包含跨日、已取消与系列成员，按开始时间、标识排序；成员显示所属系列）
node app.ts list-bookings --date 2026-10-05

# 改期：改时间、改资源或两者皆改，标识保持不变（--resource 出现即整体替换资源集合）
# 系列成员改期后仍属原系列；已取消项不能改期
node app.ts reschedule-booking B0002 --start 2026-10-13T14:00 --end 2026-10-13T15:00
node app.ts reschedule-booking B0001 --resource R0002

# 原子批量改期：按本地 JSON 清单一次改期多项预约（可互换时段、重排多项资源）
# 至少一项有变化时返回稳定且不复用的操作标识（O0001…），与改期原子保存
node app.ts reschedule-batch ./reschedule.json

# 查询批量改期操作记录：按操作先后列出未撤销/已撤销状态，项按提交顺序
# 显示预约标识、系列归属、改期前后时间与完整资源集合；空结果明确提示
node app.ts list-batch-ops

# 按操作标识整笔安全撤销（恢复原时间与原资源）；重复撤销已撤销记录成功且不改动
node app.ts undo-batch-op O0001

# 取消单项（系列成员只取消该项；释放全部资源，保留记录；重复取消成功且无变化）
node app.ts cancel-booking B0003

# 整体取消系列：仅取消该系列仍有效的成员（含单独改期者），已取消成员不变，
# 无关预约不受影响；重复整体取消成功且不变，未知系列失败
node app.ts cancel-series S0001

# 候补：固定时段 + 多资源，冲突中也可登记（不占用资源），返回 W0001…
node app.ts add-waitlist --resource R0001 --resource R0002 \
  --start 2026-10-12T10:00 --end 2026-10-12T11:00
# 相同内容重复登记视为另一项候补（W0002…）

# 弹性候补：在窗口内为全部资源寻找所需连续时长的最早安排（不占用资源）
# --window 窗口开始/窗口结束；--duration 正整数分钟且不超过窗口长度
node app.ts add-flex-waitlist --resource R0001 --resource R0002 \
  --window 2026-10-12T08:00/2026-10-12T18:00 --duration 60

# 按登记顺序查看全部候补（固定/弹性两种原请求、等待/已兑现/已取消及兑现预约标识）
node app.ts list-waitlist

# 手动处理整个队列：固定项使用原时段，弹性项取窗口内最早可行开始；
# 可兑现的按序各创建一项普通预约，受阻的继续等待
node app.ts process-waitlist

# 取消等待中的候补（记录保留）；重复取消成功且不变；取消已兑现项失败
node app.ts cancel-waitlist W0001

# 兑现产生的就是普通预约，可用现有入口改期或取消；候补保留原请求与关联，不恢复等待
node app.ts reschedule-booking B0007 --start 2026-10-13T15:00 --end 2026-10-13T16:00
node app.ts cancel-booking B0007

# 临时停用：场地维护、设备检修、人员休息（单个资源 + 起止时间，返回 C0001…）
node app.ts add-closure --resource R0001 \
  --start 2026-10-06T00:00 --end 2026-10-07T00:00

# 按开始时间、标识查看全部停用记录（资源、时间、有效/已取消状态）
node app.ts list-closures

# 取消停用：仅使该记录失效并保留历史；重复取消成功且无变化，未知标识失败
node app.ts cancel-closure C0001

# 导入本地 iCalendar 文件：为每个新 VEVENT 创建普通预约（统一使用所给资源集合）；
# 相同 UID 再次导入为重放，返回原预约当前安排与状态，不做改动
node app.ts import-ical ./examples/events.ics --resource R0001 --resource R0002
```

全局选项 `--data <文件>`（也可写 `--data=<文件>`）指定数据文件：

```sh
node app.ts --data ./shop.json list-resources
```

## 系列规则

- 标识稳定且不复用：系列 `S0001`…，成员即普通预约 `B0001`…，带 `seriesId` 归属。
- 创建时逐项校验**全部资源的连续开放覆盖**、**与既有有效预约（含其他系列成员）的冲突**及**系列成员间冲突**，继续使用左闭右开区间。
- 任一项不满足则**整批失败**：按发生顺序报告每个失败项的时间、开放不足资源、全部冲突预约及共同资源；内部冲突以双方时间定位。此时不创建任何成员、不推进标识计数。
- 仅当全部验证通过并完整保存后才返回系列标识与各项预约标识（按发生顺序关联）。
- 按周移动按营业地日历日纯算术计算，跨月、闰日、跨年准确，结果不随机器时区变化；任一项超出四位年份（`0001`–`9999`）范围即拒绝。
- 成员作为普通预约参与按日查询与占用检查；按预约标识改期/取消只影响该项；已取消项不占用资源。
- 整体取消只释放仍有效成员的资源，记录全部保留；保存失败时所有成员维持原状态与占用。

## 批量改期清单

`reschedule-batch <清单文件>` 读取本地 UTF-8 JSON 清单，对多项预约做**原子**批量改期，适合一次交换预约时段或重排多项资源安排。顶层为 `{"items": [...]}`，清单不能为空：

```json
{
  "items": [
    {"bookingId": "B0001", "start": "2026-10-12T10:00", "end": "2026-10-12T11:00", "resourceIds": ["R0001"]},
    {"bookingId": "B0002", "start": "2026-10-12T14:00", "end": "2026-10-12T15:00", "resourceIds": ["R0001", "R0002"]}
  ]
}
```

每项指定一个预约标识 `bookingId`、目标起止时间 `start`/`end` 及完整目标资源集合 `resourceIds`：

- 资源集合**整体替换**原集合，不能为空；未知或重复资源、未知或重复预约、已取消预约、非法时间均拒绝整批。
- 普通预约与不同系列成员可混合提交，不要求同时提交整个系列；标识与系列归属不变。
- 时间使用 `YYYY-MM-DDTHH:mm`，必须是真实营业地时间（年份 `0001`–`9999`），结束晚于开始，允许跨日，结果不随机器时区变化。

校验针对**整批完成后**的安排：

- 暂不把本批预约的旧占用当作障碍——逐项检查目标区间被全部目标资源的连续开放区间（重叠或相接视为连续，区间左闭右开）完整覆盖，并检查与本批之外有效预约及本批其他目标安排的冲突。
- 只有共同资源且时间重叠才冲突；已取消记录不占用资源。
- 因此即使逐项改期会被其他待改预约的旧占用阻挡，只要最终安排满足规则整批即成功（典型场景：两项预约互换时段）。
- 开放不足或冲突时按清单顺序报告全部不满足条件的项：预约标识、目标时间、开放不足资源、全部冲突预约及共同资源；批内冲突在双方项中都列明对方标识与目标时间。

全部验证并完整保存后才报告成功（按清单顺序显示每项最终安排）；整批失败时原时间、资源、状态、系列归属及占用全部不变。成功提交不创建预约或系列、不推进预约/系列/候补/停用标识计数，未提交预约不变；再次提交已生效的相同清单，在预约仍有效且安排未变时成功且无业务变化（幂等）。重新启动后按日及系列查询反映新安排；单项取消与整体取消系列仍按原归属释放资源。

## 批量改期记录与安全撤销

- 批量改期**至少一项有变化**时，生成稳定、不复用的操作标识 `O0001`…，与新安排在**同一次原子保存**中落盘后才报告成功并显示操作标识与最终安排；记录包含**全部提交项**的预约标识、提交时系列归属、改期前后时间与完整资源集合及清单顺序。
- **无变化提交仍成功**并显示完整安排，但不建记录、不改文件、不推进操作计数；校验或保存失败不留任何记录。
- 后续的单项/批量改期或取消都**保留**记录；记录快照与现状不同**不算数据损坏**。撤销后重提交相同清单若产生变化，生成**新的**操作标识——不按清单路径或内容复用旧操作。
- `list-batch-ops` 按操作先后列出全部记录及未撤销/已撤销状态；项按提交顺序显示改期前后安排（时间、完整资源、系列归属）；无记录时明确提示。
- `undo-batch-op <操作标识>` 允许撤销**任意未撤销记录**：
  - **前置一致性**：全部涉及预约须仍**有效**，且当前时间、资源集合、系列归属与该记录的**改期后安排**完全一致，否则**整笔拒绝**并列出全部不一致预约（不能复活已取消预约）。按**当前值**比对——期间改动后又恢复一致仍可撤销。
  - **恢复可行性**：将全部涉及预约恢复至各自**原时间与原资源**，按整笔恢复后的最终安排校验：排除其当前占用，**允许互换时段**；各资源须被连续实际可用时间完整覆盖（开放合并重叠或相接后扣除有效停用并集）；区间左闭右开，只有共同资源且时间重叠才冲突；同时检查批内与批外有效预约。受阻时按提交顺序列出全部失败项、开放不足资源与相关停用标识和时间、全部冲突预约及共同资源，**整笔不变**。
  - 通过后原子保存恢复安排与“已撤销”状态，显示各项恢复后的完整安排；**不新增撤销记录、不改变任何标识计数**；预约标识、有效状态、系列归属及候补原请求和兑现关联不变，无关预约不变，**不自动处理候补**。
  - **重复撤销**已撤销记录成功且不触碰当前安排（即使之后又有改期）；未知记录失败。

## 候补规则

候补有两种，**共用同一条登记顺序**：`add-waitlist` 登记**固定时段**候补，`add-flex-waitlist` 登记**弹性时段**候补；`process-waitlist` 在需要时手动处理整个队列。普通创建、改期或取消预约、新增或取消停用都**不会**自动处理候补。

### 固定时段候补（add-waitlist）

- 登记时指定至少一个**不同的已登记资源**及起止时间，全部资源须被其连续开放区间（重叠或相接视为连续）完整覆盖；未知或重复资源、开放不足、非法时间一律拒绝。
- **当前有预约冲突或资源空闲均可登记**——候补不占用资源，开放覆盖是唯一硬性前提。时间使用 `YYYY-MM-DDTHH:mm`（年份 `0001`–`9999`，真实有效、结束晚于开始、允许跨日、不随机器时区变化）。

### 弹性时段候补（add-flex-waitlist）

- 指定至少一个**不同的已登记资源**、一个窗口 `--window 开始/结束`（`YYYY-MM-DDTHH:mm/YYYY-MM-DDTHH:mm`，年份 `0001`–`9999`，真实有效、结束晚于开始、允许跨日、与机器时区无关）及所需连续时长 `--duration`（**不超过窗口长度的正整数分钟**）。
- **登记忽略预约占用**，但窗口内全部资源的**共同实际可用时间**（各资源开放区间合并重叠或相接后扣除其有效停用并集，再取交集并裁剪到窗口内；**无需整窗开放**）必须存在能完整容纳该时长的连续区间，不能由空隙拼接；否则拒绝并列出窗口内全部最大共同实际可用区间及分钟数（空集明确提示）。
- 登记不占资源。后续新增停用使窗口不再可行，只影响兑现，**不会使记录损坏或被删除**。

### 两种候补共同规则

- 返回稳定且不复用的候补标识 `W0001`…；**重复登记相同内容视为另一项候补**（各自独立排队）；固定与弹性按成功登记先后混排在同一条队列中。
- `process-waitlist` 按**成功登记顺序**逐项重查，扣除**当前有效预约**（含系列成员，已取消不占用）及**本轮已选项占用**，区间均为左闭右开：
  - **固定项使用原时段**：要求全部资源被实际可用时间完整覆盖，且与有效预约及本轮已选项无共同资源时间重叠。
  - **弹性项取窗口内最早可行的开始分钟**（结束不超出窗口）：在窗口内的共同实际可用时间上扣除有效预约与本轮已选项占用后，取第一段长度足够的共同空闲区间的起点；全部资源必须**同时**连续可用，不能拼接空隙。
- 全部资源可用才选中；**受阻项继续等待，随后继续检查后项**——例如 W0001 受阻而 W0002 可行时，W0002 本轮兑现，绝不为增加兑现数量而重排队列或让后者顶掉、移动前者。
- 每个选中项各生成一项**普通预约**（`B…`，不加入系列、不改动任何原预约）；新预约、候补的已兑现状态及对应预约标识**一并原子保存后才报告成功**。
- 结果按队列顺序展示：选中项给出候补标识与预约标识、实际时间和完整资源（弹性项另附原窗口与时长）。等待项中，**弹性项按最终安排列出窗口内全部最大共同空闲区间及分钟数**（按开始时间排序，空集明确提示）；**固定项列出开放不足资源与全部阻挡**（含本轮后项产生的预约）。
- **没有可兑现项也成功**：明确说明，且不改变任何记录、占用或标识计数。
- `list-waitlist` 按登记顺序显示全部候补的标识、种类与两种原请求（固定时段，或弹性窗口+时长）、资源、等待/已兑现/已取消状态及兑现后的预约标识（含其当前实际时间）；空队列明确提示。
- `cancel-waitlist` 只能取消等待项（固定或弹性均可），记录保留；重复取消已取消项成功且不变；未知标识或取消**已兑现**项失败。
- 兑现后的预约就是普通预约，可用 `reschedule-booking`/`reschedule-batch`/`cancel-booking` 处理；候补始终保留原请求与关联、**不恢复等待**。重复执行 `process-waitlist` 不会为已兑现或已取消项再次创建预约。
- 重启后队列顺序、状态与关联仍在。候补状态、种类或关联非法，时长缺失/非正整数/超过窗口长度，数据损坏、保存失败均明确拒绝，原文件、全部记录、占用与标识计数不变。

## 停用规则

`add-closure` 为一个已登记资源登记一段**临时停用**（场地维护、设备检修、人员休息），`cancel-closure` 使其失效。

- 登记指定**一个**已登记资源及起止时间，**不要求该区间原本开放**。时间使用 `YYYY-MM-DDTHH:mm`（年份 `0001`–`9999`，真实有效、结束晚于开始、允许跨日、不随机器时区变化）。
- 登记前检查该资源的**全部有效预约**（含系列成员与候补兑现预约；已取消不阻挡；区间左闭右开，端点相接不算重叠）：有时间重叠即拒绝，列出全部受影响预约标识及时间，**不改期或取消它们**。
- 返回稳定且不复用的停用标识 `C0001`…；**相同内容再次登记也是另一记录**，允许停用重叠或相接。
- 资源的**实际可用时间** = 原开放区间合并后扣除全部有效停用区间的并集（原开放记录保留）。创建预约、单项及批量改期、创建系列、登记及处理候补均按实际可用时间检查全部资源的完整覆盖；停用导致不足时列出受影响资源及相关有效停用标识和时间。
- 已有候补不因新增停用而删除、取消或被判作损坏数据；处理时受阻项继续等待并检查后项，保留登记顺序。取消停用后候补仅在再次手动 `process-waitlist` 时尝试兑现，已兑现关联不变且不恢复等待。
- `cancel-closure` 仅使指定记录失效并保留历史；重复取消成功且无变化，未知标识失败。其他重叠停用仍有效，恢复范围不超出原开放时间；取消不自动创建预约或处理候补。
- `list-closures` 按开始时间、标识列出全部记录的资源、时间与有效/已取消状态；空结果明确提示。

## iCalendar 导入

`import-ical <iCalendar 文件> --resource <标识> [--resource <标识> ...]` 读取本地 UTF-8 的 iCalendar 文件，为每个新事件创建一项**普通预约**（不加入系列、不自动处理候补），全部新事件统一使用命令行给定的资源集合（至少一个**不同的已登记资源**）。简短文件示例（另见 `examples/events.ics`）：

```
BEGIN:VCALENDAR
VERSION:2.0
BEGIN:VEVENT
UID:meeting-001@example.com
DTSTART:20261012T100000
DTEND:20261012T110000
END:VEVENT
END:VCALENDAR
```

文件规则：

- 顶层为 `VERSION:2.0` 的 `VCALENDAR`，至少含一个**独立 VEVENT**；每项须有一个**非空 UID、DTSTART 和 DTEND**。
- 时间仅支持**浮动的 `YYYYMMDDTHHmmss`**：秒为 `00`，年份 `0001`–`9999`，真实有效、结束晚于开始、允许跨日、不随机器时区变化。
- 支持 **CRLF 或 LF** 行尾、**标准折行**（续行以空格或制表符开头）与 **UID 文本转义**（`\\`、`\,`、`\;`、`\n`）；属性名忽略大小写，**解码后 UID 区分大小写**。
- 描述属性（`DESCRIPTION`）忽略；**全天**（`VALUE=DATE`）、**时区**（`TZID`、UTC 写法）、**重复相关属性**（`RRULE`/`RDATE`/`EXDATE`/`EXRULE`/`RECURRENCE-ID`）、**取消事件**（`STATUS:CANCELLED` 或 `METHOD:CANCEL`）及**事件内嵌套组件**（如 `VALARM`）一律拒绝；结构错误、关键属性（UID/DTSTART/DTEND）重复或文件内 UID 重复均**整批失败**。

身份与重放：

- UID 在同一数据文件中**永久关联首次生成的预约**（身份不依赖导入文件路径），并持久保留**首次导入的时间与资源集合**。
- 相同 UID 且时间、资源集合与首次导入一致为**重放**（资源顺序、折行与转义写法差异不算变化）：返回原预约的当前安排与状态，**不做任何改动**——即使该预约已被改期、取消或随批量改期撤销，也不复活、不重建。
- 相同 UID 的**时间或资源集合不同则整批拒绝**，绝不覆盖本地安排。
- 文件可**混合新项与重放项**：仅新项接受目标校验，重放项关联的旧预约按当前状态与安排参与占用。

校验与落盘：

- 新项须被全部资源的连续**实际可用时间**（开放合并后扣除有效停用并集）完整覆盖；检查批内及全部既有有效预约，只有共同资源的左闭右开区间重叠才冲突。
- 受阻时**按文件顺序**报告全部失败 UID、时间、不足资源及相关停用标识和时间、全部冲突与共同资源；批内冲突列双方 UID。
- 新预约与导入身份**一次原子保存**后才成功，按文件顺序显示 UID、预约标识、完整安排及新增或重放；**全为重放时不写文件、不推进计数**。
- 旧数据无需迁移（无 `imports` 字段的旧文件视为空）；导入记录的快照与预约现状不同合法，但重复 UID、非法或重复预约关联及非法快照视为**数据损坏**。输入、读取、校验或保存失败保留原文件、全部记录及计数。

## 维护说明

- 创建系列、批量改期、安全撤销与 iCalendar 导入共用同一套**无写入副作用**的批次校验 `validateBatchTargets`（app.ts“多目标批次校验”一节）：针对全部目标生效后的安排，统一检查实际可用覆盖（开放合并后扣除有效停用并集）、批外占用（排除本批涉及预约的当前占用，允许整批交换）与批内冲突（仅共同资源左闭右开重叠，双方都报告）。该函数只读，不修改目标、业务记录或计数。
- 各入口只负责自己的业务定位与渲染（系列按发生顺序、改期与撤销按提交顺序、导入按文件顺序）以及校验通过后的提交（改内存、原子落盘、输出）；UID 一致性、撤销的当前值匹配与重复撤销判定仍留在各入口。新增多目标入口时复用 `validateBatchTargets`，不要再写整批可行性循环。

## 数据与退出码

- 已有数据文件**无需手工迁移**：旧文件（无 `series`、`waitlist`、`closures`、`batchOps`、`imports` 字段，或旧候补记录无 `kind`/弹性字段）可直接继续查询和修改，缺少候补、停用、批量改期或导入记录时视为空且不补造历史，旧候补记录一律按固定时段候补处理；各旧入口读写均不会丢失候补、停用、批量改期操作记录及其撤销状态与导入身份。
- 资源、预约、系列、候补、停用与批量改期操作标识稳定且不复用（`R0001`…、`B0001`…、`S0001`…、`W0001`…、`C0001`…、`O0001`…）；撤销不回收也不推进操作计数。
- 预约必须被每个所选资源的开放区间完整覆盖；冲突时报出所有冲突预约标识及共同资源，且不会产生部分预约。
- 数据文件不存在按空数据处理；**损坏或结构非法时直接失败并原样保留文件**（含候补状态、种类、时长或关联非法，批量改期记录的结构、引用或快照非法，以及导入记录的 UID 重复、预约关联非法或重复、快照非法）。修改先写临时文件再原子替换，校验或保存失败不会改动任何记录、占用、记录状态或标识计数。
- 改期清单不可读、损坏（非法 JSON）或内容非法时明确失败；批量改期校验或保存失败保留原数据文件及全部记录和计数，不留下部分改期、不留下操作记录。撤销校验或保存失败时原文件、全部安排、记录状态和计数不变。iCalendar 文件不可读、结构非法、UID 与首次导入不一致或新事件受阻时整批失败，原文件、全部记录及计数不变。
- 无参数、`-h`、`--help` 显示帮助；各入口拒绝未知选项与多余位置参数。
- 退出码：`0` 成功；`1` 业务失败（空名称、未知/重复资源、非法时间或次数、开放不足、冲突、超出四位年份、未知系列、未知候补、取消已兑现候补、未知批量改期操作、撤销涉及预约与记录不一致或恢复安排受阻、批量改期记录结构或快照非法、iCalendar 文件不可读/结构非法、UID 与首次导入不一致、新事件开放不足或冲突、数据损坏等，附带原因）；`2` 用法错误（未知参数、缺少选项、多余位置参数）。
