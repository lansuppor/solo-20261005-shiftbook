# shiftbook

本地多资源预约命令行工具。管理场地、设备、人员三类资源的开放区间，并在其之上创建、改期、取消预约与按日查询；支持按周重复的多资源**预约系列**、单次固定时段与弹性窗口的多资源**候补队列**（两种候补共用一条登记顺序）、场地维护、设备检修、人员休息等**资源临时停用**（`add-closure` 可附一个本地弹性改期清单，一次原子提交停用与替代安排，规则与记录同 `reschedule-flex`）、批量改期的**操作记录与安全撤销**、本地 **iCalendar 文件导入**（独立事件生成普通预约、按周 `RRULE`+`EXDATE` 事件生成系列，同一 UID 的按周主事件可配若干 `RECURRENCE-ID` 单次改期例外；UID 永久关联首次请求——含按原发生关联的例外起止集合，重复导入自动识别为重放）与**已导入按周系列的本地 iCalendar 导出**（`export-ical`，按已解码 UID 选择一个已导入按周系列，把保存本地变更后的当前安排写为 VCALENDAR；只读快照，主事件保留首次 UID/首项时间/COUNT，本地改期按相对原周展开的差异输出当前例外，取消成员并入 EXDATE）、候选资源组合的**最早可行时段查询**（`find-slot`，只读）、多项弹性预约的**联合排程与原子创建**（`schedule-flex`，按本地清单一次求解整单并创建全部预约，可附项间先后与衔接间隔关系）、尽量少改动既有预约的**弹性批量改期**（`reschedule-flex`，按本地清单为整单求解最终安排，先最小化变化预约数量再取字典序最小方案），以及资源使用率与繁忙时段**统计**（`usage-stats`，只读）。

- TypeScript 编写，使用 Node.js 24 直接运行（类型擦除），**无外部运行依赖**。
- 数据保存在本地单个 JSON 文件中（默认 `shiftbook-data.json`，可用 `--data` 指定）。
- 同一数据文件的修改入口**多进程互斥**（锁文件写入保护），并发预约或改期不会覆盖彼此已保存的安排。
- 时间为与机器时区无关的营业地时间：日期时间 `YYYY-MM-DDTHH:mm`，查询日期 `YYYY-MM-DD`，允许跨日。
- 区间左闭右开；开放区间重叠或相接视为连续开放；仅共同资源上的**实际占用**重叠才算冲突。
- 每个资源可为每个预约设置**预约前准备**与**预约后整理**分钟（`add-resource --prep/--teardown`，非负安全整数，省略或旧资源缺字段为 0，持久化保留）。预约记录始终保存活动起止；每个所用资源对该预约的实际占用分别为“活动开始减该资源自己的准备”至“活动结束加该资源自己的整理”（左闭右开，按资源分别扩张，不取最大缓冲统一扩张），扩张后端点相接可行。

```sh

```

## 命令

```sh
# 登记资源（--open 可重复，至少一个；类型可写 venue/equipment/person 或 场地/设备/人员）
# --prep/--teardown 为该资源每个预约的预约前准备/预约后整理分钟，可省略（默认 0）
node app.ts add-resource --type 场地 --name 一号会议室 \
  --open 2026-10-05T08:00/2026-10-05T12:00 \
  --open 2026-10-05T13:00/2026-10-06T20:00 \
  --prep 15 --teardown 15
node app.ts list-resources

# 创建预约（可同时指定多个不同资源；一次占用全部）
node app.ts create-booking --resource R0001 --resource R0002 \
  --start 2026-10-05T10:00 --end 2026-10-05T11:00

# 按周重复系列：首项起止时间 + 正整数次数（含首项）+ 至少一个已登记资源
# 自首项起，每项相对前一项将起止时间同时后移 7 个营业地日历日，
# 时刻与跨日长度不变，全部成员使用相同资源
node app.ts create-series --resource R0001 --resource R0002 \
  --start 2026-10-05T10:00 --end 2026-10-05T11:00 --count 4
# -> 返回系列标识 S0001 及按发生顺序关联的各成员预约标识 B0001..B0004

# 查询系列：全部成员、资源、时间与状态，按当前开始时间、预约标识排序
# （含单独改期或取消的成员）
node app.ts list-series

# 按日查询（包含跨日、已取消与系列成员，按开始时间、标识排序；成员显示所属系列）
node app.ts list-bookings --date 2026-10-05

# 改期：改时间、改资源或两者皆改，标识保持不变（--resource 出现即整体替换资源集合）
# 系列成员改期后仍属原系列；已取消项不能改期
node app.ts reschedule-booking B0002 --start 2026-10-13T14:00 --end 2026-10-13T15:00
node app.ts reschedule-booking B0001 --resource R0002

# 原子批量改期：按本地 JSON 清单一次改期多项预约（可互换时段、重排多项资源）
# 至少一项有变化时返回稳定且不复用的操作标识（O0001…），与改期原子保存
node app.ts reschedule-batch ./reschedule.json

# 弹性批量改期：按本地 JSON 清单为多项既有预约求解整单最终安排
# （每项给出预约标识、目标窗口与有顺序的候选资源组，时长保持预约当前长度；
# 先尽量少改动既有预约，再取字典序最小方案），记录与撤销规则同批量改期
node app.ts reschedule-flex ./reschedule-flex.json

# 查询批量改期操作记录：按操作先后列出未撤销/已撤销状态，项按提交顺序
# 显示预约标识、系列归属、改期前后时间与完整资源集合；空结果明确提示
node app.ts list-batch-ops

# 按操作标识整笔安全撤销（恢复原时间与原资源）；重复撤销已撤销记录成功且不改动
node app.ts undo-batch-op O0001

# 取消单项（系列成员只取消该项；释放全部资源，保留记录；重复取消成功且无变化）
node app.ts cancel-booking B0003

# 整体取消系列：仅取消该系列仍有效的成员（含单独改期者），已取消成员不变，
# 无关预约不受影响；重复整体取消成功且不变，未知系列失败
node app.ts cancel-series S0001

# 候补：固定时段 + 多资源，冲突中也可登记（不占用资源），返回 W0001…
node app.ts add-waitlist --resource R0001 --resource R0002 \
  --start 2026-10-12T10:00 --end 2026-10-12T11:00
# 相同内容重复登记视为另一项候补（W0002…）

# 弹性候补：在窗口内为全部资源寻找所需连续时长的最早安排（不占用资源）
# --window 窗口开始/窗口结束；--duration 正整数分钟且不超过窗口长度
node app.ts add-flex-waitlist --resource R0001 --resource R0002 \
  --window 2026-10-12T08:00/2026-10-12T18:00 --duration 60

# 按登记顺序查看全部候补（固定/弹性两种原请求、等待/已兑现/已取消及兑现预约标识）
node app.ts list-waitlist

# 手动处理整个队列：固定项使用原时段，弹性项取窗口内最早可行开始；
# 可兑现的按序各创建一项普通预约，受阻的继续等待
node app.ts process-waitlist

# 取消等待中的候补（记录保留）；重复取消成功且不变；取消已兑现项失败
node app.ts cancel-waitlist W0001

# 候选资源组合的最早可行时段查询（只读，不创建任何记录）：
# 窗口 + 所需连续分钟数 + 有顺序的需求组（每组 --group 列出可任选其一的候选）
node app.ts find-slot --window 2026-10-12T08:00/2026-10-12T18:00 \
```

## 多进程写入保护

同一数据文件的所有**修改入口**（登记资源、创建/改期/取消预约与系列、批量改期与弹性批量改期及撤销、候补登记/取消/处理、停用登记/取消、iCalendar 导入、联合排程）以数据文件为单位**互斥**执行：

- 修改入口先取得写入保护（锁文件 `<数据文件>.lock`），再**读取最新数据**、做业务校验、分配标识并原子保存，命令结束统一释放——正常结束、校验失败、保存失败都会释放本次保护。保护覆盖“读取决策所需状态 → 校验 → 分配标识 → 原子保存”全过程，而非只保护最后写文件。
- 相对路径、绝对路径与含 `./..` 的等价写法**共享同一把锁**；不同数据文件互不影响；数据文件尚不存在时同样受保护。
- 竞争可等待，但 **5 秒内未取得保护即以退出码 1 报告“正被其他进程占用”**，可稍后重试；竞争失败不产生记录、不消耗标识，也不影响其他进程已提交的内容。两个可并存的请求会先后成功且都保留；共同资源重叠的两个预约最多一个成功，另一个重试时按最新占用报告冲突。
- **查询不等待保护**：保存是先写临时文件再原子替换，查询只读到提交前或提交后的完整快照；帮助与用法错误也不依赖保护（退出码 0/1/2 不变）。
- 进程异常退出可能留下**残留保护**（锁文件未删），此时修改入口会一直报告占用。确认原写入进程已退出后，用本地恢复入口解除：

```sh
node app.ts --data ./shop.json recover-lock
```

`recover-lock` 仅在确认原写入进程**已退出**时解除残留保护；进程仍存活或无法确认（如非本机、无权限查询、锁内容无法辨认）时明确拒绝，**不按保护存在时长抢占**。恢复不重放旧命令、不改业务数据或标识计数；没有残留保护时明确提示且不改动（退出码 0、无操作）。

恢复交接同样是互斥的：

- 恢复入口之间以**恢复协调文件**（`<锁文件>.recover`，独占创建）互斥，任一时刻至多一个恢复者；持有者在互斥内**重新核对目标后**才删除锁文件。持有协调文件期间，原持有者已确认退出（不会再释放）、其他恢复者进不了互斥、新写入者只能在锁文件不存在时取得——因此互斥内的删除恰好删除本次确认的那一份残留保护。
- 多个 `recover-lock` 与修改命令交错时，恢复只解除**已确认原持有者退出的那次保护**：旧保护被另一请求解除、新写入者取得保护后，较早的恢复请求**不会删除新保护**（发现目标更替即以退出码 1 说明原因，不宣称解除新保护），第三写入者也不能越过新保护。
- 恢复者自身异常退出会留下残留协调文件：后续恢复入口在确认其持有者已退出后**自动清理并完成恢复**，无需人工删文件；协调文件的持有者存活、非本机或内容无法辨认时同样拒绝。
- 释放与恢复都只删除自己确认的那一份，绝不误删其他进程后来取得的保护。

## 预约前准备与预约后整理（资源缓冲时间）

每个资源可以分别设置**预约前准备分钟**与**预约后整理分钟**（登记资源时的 `--prep`、`--teardown`，非负安全整数；省略或旧资源缺字段均为 `0`）。设置持久保存在数据文件中，读写与重启都保留；非法命令行值（小数、负数等）拒绝，数据文件中已持久化的字段非法则视为**文件损坏**（原文件保留，拒绝加载）。

- **预约记录保存的始终是活动起止**：`create-booking`、查询、操作快照、iCalendar 导出看到的 `start/end` 都是活动时间，准备/整理不写进预约记录，UID 身份、系列归属与候补关联也只按活动时间。
- 对一项使用多个资源的预约，**每个所用资源的实际占用分别**为 `[活动开始 − 该资源准备, 活动结束 + 该资源整理)`（左闭右开）。不同资源缓冲不同时按各自缓冲分别扩张，**绝不取多个资源的最大缓冲统一扩张**。
- 实际占用必须被该资源“开放区间合并（重叠或相接）后扣除有效停用”的连续区间**完整覆盖**；实际占用越出 `0001`–`9999` 年范围（例如准备早于公元 1 年）即拒绝。停用记录自身不扩张。
- 冲突只看**共同资源上的双方实际占用**：两预约活动时间不重叠但某共同资源的准备/整理区间重叠，仍冲突；扩张后的端点恰好相接（一方实际占用结束恰为另一方实际占用开始）可行。取消的预约、未兑现候补不占用。
- `find-slot`、弹性候补、`schedule-flex`、`reschedule-flex`、`add-closure` 附清单的**窗口只限制活动起止**；准备/整理可以伸出窗口，但伸出部分仍须落在该资源的实际可用时间内。各求解器按“活动坐标”计算：实际可用段 `[a,b)` 对活动等价于 `[a+准备, b−整理)`，其他预约活动 `[bs,be)` 阻挡 `[bs−(准备+整理), be+(准备+整理))`；项间衔接关系仍按前项**活动结束**到后项**活动开始**计算，与缓冲无关。最早开始与字典序取舍、弹性批量改期的最少变化仍按活动时间与资源集合判断。
- 候补登记忽略预约占用；弹性候补登记时要求窗口内全部资源扣除各自前后预留后的共同可供活动区间能容纳完整时长；兑现按登记顺序、取窗口内最早可行活动开始。弹性等待诊断显示的是“扣除预约占用及各资源前后预留后、可供活动使用的最大共同区间”。
- `add-closure` 按资源上的**实际占用**识别受影响预约（停用区间本身不扩张），附清单时受影响预约必须全部列入并计入拟停用求解；`undo-batch-op` 只恢复预约、不取消停用（原安排的实际占用仍被停用阻挡时整笔拒绝）。
- `usage-stats` 按每个资源上的**实际占用**计时、按营业日拆分并计算同时占用峰值；`list-bookings`、`list-series`、操作快照、iCalendar 导出仍只显示活动起止。

## 系列规则

- 标识稳定且不复用：系列 `S0001`…，成员即普通预约 `B0001`…，带 `seriesId` 归属。
- 创建时逐项校验**全部资源的连续开放覆盖**、**与既有有效预约（含其他系列成员）的冲突**及**系列成员间冲突**，继续使用左闭右开区间。
- 任一项不满足则**整批失败**：按发生顺序报告每个失败项的时间、开放不足资源、全部冲突预约及共同资源；内部冲突以双方时间定位。此时不创建任何成员、不推进标识计数。
- 仅当全部验证通过并完整保存后才返回系列标识与各项预约标识（按发生顺序关联）。
- 按周移动按营业地日历日纯算术计算，跨月、闰日、跨年准确，结果不随机器时区变化；任一项超出四位年份（`0001`–`9999`）范围即拒绝。
- 成员作为普通预约参与按日查询与占用检查；按预约标识改期/取消只影响该项；已取消项不占用资源。
- 整体取消只释放仍有效成员的资源，记录全部保留；保存失败时所有成员维持原状态与占用。

## 批量改期清单

`reschedule-batch <清单文件>` 读取本地 UTF-8 JSON 清单，对多项预约做**原子**批量改期，适合一次交换预约时段或重排多项资源安排。顶层为 `{"items": [...]}`，清单不能为空：

```json
{
  "items": [
    {"bookingId": "B0001", "start": "2026-10-12T10:00", "end": "2026-10-12T11:00", "resourceIds": ["R0001"]},
    {"bookingId": "B0002", "start": "2026-10-12T14:00", "end": "2026-10-12T15:00", "resourceIds": ["R0001", "R0002"]}
  ]
}
```

每项指定一个预约标识 `bookingId`、目标起止时间 `start`/`end` 及完整目标资源集合 `resourceIds`：

- 资源集合**整体替换**原集合，不能为空；未知或重复资源、未知或重复预约、已取消预约、非法时间均拒绝整批。
- 普通预约与不同系列成员可混合提交，不要求同时提交整个系列；标识与系列归属不变。
- 时间使用 `YYYY-MM-DDTHH:mm`，必须是真实营业地时间（年份 `0001`–`9999`），结束晚于开始，允许跨日，结果不随机器时区变化。

校验针对**整批完成后**的安排：

- 暂不把本批预约的旧占用当作障碍——逐项检查目标区间被全部目标资源的连续开放区间（重叠或相接视为连续，区间左闭右开）完整覆盖，并检查与本批之外有效预约及本批其他目标安排的冲突。
- 只有共同资源且时间重叠才冲突；已取消记录不占用资源。
- 因此即使逐项改期会被其他待改预约的旧占用阻挡，只要最终安排满足规则整批即成功（典型场景：两项预约互换时段）。
- 开放不足或冲突时按清单顺序报告全部不满足条件的项：预约标识、目标时间、开放不足资源、全部冲突预约及共同资源；批内冲突在双方项中都列明对方标识与目标时间。

全部验证并完整保存后才报告成功（按清单顺序显示每项最终安排）；整批失败时原时间、资源、状态、系列归属及占用全部不变。成功提交不创建预约或系列、不推进预约/系列/候补/停用标识计数，未提交预约不变；再次提交已生效的相同清单，在预约仍有效且安排未变时成功且无业务变化（幂等）。重新启动后按日及系列查询反映新安排；单项取消与整体取消系列仍按原归属释放资源。

## 批量改期记录与安全撤销

- 批量改期与弹性批量改期（`reschedule-batch` / `reschedule-flex`）**至少一项有变化**时，生成稳定、不复用的操作标识 `O0001`…，与新安排在**同一次原子保存**中落盘后才报告成功并显示操作标识与最终安排；记录包含**全部提交项**的预约标识、提交时系列归属、改期前后时间与完整资源集合及清单顺序。
- **无变化提交仍成功**并显示完整安排，但不建记录、不改文件、不推进操作计数；校验或保存失败不留任何记录。
- 后续的单项/批量改期或取消都**保留**记录；记录快照与现状不同**不算数据损坏**。撤销后重提交相同清单若产生变化，生成**新的**操作标识——不按清单路径或内容复用旧操作。
- `list-batch-ops` 按操作先后列出全部记录及未撤销/已撤销状态；项按提交顺序显示改期前后安排（时间、完整资源、系列归属）；无记录时明确提示。
- `undo-batch-op <操作标识>` 允许撤销**任意未撤销记录**：
  - **前置一致性**：全部涉及预约须仍**有效**，且当前时间、资源集合、系列归属与该记录的**改期后安排**完全一致，否则**整笔拒绝**并列出全部不一致预约（不能复活已取消预约）。按**当前值**比对——期间改动后又恢复一致仍可撤销。
  - **恢复可行性**：将全部涉及预约恢复至各自**原时间与原资源**，按整笔恢复后的最终安排校验：排除其当前占用，**允许互换时段**；各资源须被连续实际可用时间完整覆盖（开放合并重叠或相接后扣除有效停用并集）；区间左闭右开，只有共同资源且时间重叠才冲突；同时检查批内与批外有效预约。受阻时按提交顺序列出全部失败项、开放不足资源与相关停用标识和时间、全部冲突预约及共同资源，**整笔不变**。
  - 通过后原子保存恢复安排与“已撤销”状态，显示各项恢复后的完整安排；**不新增撤销记录、不改变任何标识计数**；预约标识、有效状态、系列归属及候补原请求和兑现关联不变，无关预约不变，**不自动处理候补**。
  - **重复撤销**已撤销记录成功且不触碰当前安排（即使之后又有改期）；未知记录失败。

## 弹性批量改期（reschedule-flex）

`reschedule-flex <改期清单文件>` 读取本地 UTF-8 JSON 清单，为**整份清单**的既有预约求解**尽量少改动**的最终安排并原子改期，适合时间、资源都可浮动但希望尽量保持现状的批量调整。顶层为 `{"items": [...]}`，清单非空且有顺序；每项给出一个预约标识、一个目标窗口与有顺序的候选资源组，**时长保持预约当前长度**：

```json
{
  "items": [
    {"bookingId": "B0001", "window": "2026-10-12T08:00/2026-10-12T18:00", "groups": [["R0001", "R0002"], ["R0003"]]},
    {"bookingId": "B0002", "window": "2026-10-12T09:00/2026-10-12T12:00", "groups": [["R0001"]]}
  ]
}
```

清单规则：

- 每项字段：`bookingId`（要改期的预约标识；**未知、重复或已取消预约整单拒绝**；普通预约、系列成员、导入预约与候补兑现预约可混合提交，不要求同时提交整个系列）、`window`（`YYYY-MM-DDTHH:mm/YYYY-MM-DDTHH:mm`，年份 `0001`–`9999`，真实有效、结束晚于开始、允许跨日、与机器时区无关，**长度不得小于预约当前时长**）、`groups`（有顺序的候选资源组数组，每组是一个候选资源标识数组）。
- **至少一组、每组非空**；组内重复或未知资源整单拒绝（退出码 1）；资源可跨组、跨项出现，但**一项所选资源须互不相同**。存在未知字段、清单不可读或损坏同样整单失败。

求解与取舍：

- 求解针对**整单最终安排**：**排除本批旧占用**，其余有效预约按现状阻挡（取消记录与未兑现候补不阻挡）；开放区间重叠或相接先合并，再扣除**有效停用**；每项**完整落在自身窗口内**，每组恰选一个候选，全部所选资源**同时连续可用且全程固定**（不中途更换资源、不拼接间断时间）；本批之间仅**共同资源的左闭右开时间重叠**才冲突，端点相接可行。
- **先最小化变化预约数量**：起止时间或完整资源集合不同才算变化，**资源顺序不计**——现状可行的预约保持原位（哪怕它的开始不是窗口内最早）。数量相同再按**清单顺序**逐项比较：先比该项**开始分钟**，再按候选资源组顺序以**字符串字典序**比资源标识，第一处差异取较小者，取字典序最小的完整方案。**候选书写顺序不影响结果**。

落盘与结果：

- 只改本批预约的**时间与资源**：标识、状态、系列归属、导入身份与首次请求、候补原请求及兑现关联全部保留，**不新建预约、不自动处理候补**。
- **至少一项有变化**时，将全部提交项的前后完整安排、系列归属及清单顺序记为一条稳定、不复用的**批量改期操作记录**（`O0001`…，与 `reschedule-batch` 的记录同表），与改期在**同一次原子保存**中落盘后才退出 0，并按清单顺序显示各项预约标识、起止时间与按组对应的资源及操作标识；仅推进操作计数，旧记录保留。记录可用 `list-batch-ops` 查询、`undo-batch-op` 整笔安全撤销（规则同批量改期记录）；**每次提交按当前状态求解**，撤销后重提产生变化分配**新的**操作标识。
- **无变化成功**（全部项安排均与现状一致）同样按清单顺序显示完整安排，但**不写文件、不建记录、不推进计数**。
- **无整体解明确提示并退出 1**，不改动任何预约；非法输入、读取失败、损坏数据、保护竞争或保存失败均退出 1 并说明原因，用法错误退出 2。失败不产生本次变更或计数变化，取得保护后的读取、校验或保存失败保持数据文件原样。

## 候补规则

候补有两种，**共用同一条登记顺序**：`add-waitlist` 登记**固定时段**候补，`add-flex-waitlist` 登记**弹性时段**候补；`process-waitlist` 在需要时手动处理整个队列。普通创建、改期或取消预约、新增或取消停用都**不会**自动处理候补。

### 固定时段候补（add-waitlist）

- 登记时指定至少一个**不同的已登记资源**及起止时间，全部资源须被其连续开放区间（重叠或相接视为连续）完整覆盖；未知或重复资源、开放不足、非法时间一律拒绝。
- **当前有预约冲突或资源空闲均可登记**——候补不占用资源，开放覆盖是唯一硬性前提。时间使用 `YYYY-MM-DDTHH:mm`（年份 `0001`–`9999`，真实有效、结束晚于开始、允许跨日、不随机器时区变化）。

### 弹性时段候补（add-flex-waitlist）

- 指定至少一个**不同的已登记资源**、一个窗口 `--window 开始/结束`（`YYYY-MM-DDTHH:mm/YYYY-MM-DDTHH:mm`，年份 `0001`–`9999`，真实有效、结束晚于开始、允许跨日、与机器时区无关）及所需连续时长 `--duration`（**不超过窗口长度的正整数分钟**）。
- **登记忽略预约占用**，但窗口内全部资源的**共同实际可用时间**（各资源开放区间合并重叠或相接后扣除其有效停用并集，再取交集并裁剪到窗口内；**无需整窗开放**）必须存在能完整容纳该时长的连续区间，不能由空隙拼接；否则拒绝并列出窗口内全部最大共同实际可用区间及分钟数（空集明确提示）。
- 登记不占资源。后续新增停用使窗口不再可行，只影响兑现，**不会使记录损坏或被删除**。

### 两种候补共同规则

- 返回稳定且不复用的候补标识 `W0001`…；**重复登记相同内容视为另一项候补**（各自独立排队）；固定与弹性按成功登记先后混排在同一条队列中。
- `process-waitlist` 按**成功登记顺序**逐项重查，扣除**当前有效预约**（含系列成员，已取消不占用）及**本轮已选项占用**，区间均为左闭右开：
  - **固定项使用原时段**：要求全部资源被实际可用时间完整覆盖，且与有效预约及本轮已选项无共同资源时间重叠。
  - **弹性项取窗口内最早可行的开始分钟**（结束不超出窗口）：在窗口内的共同实际可用时间上扣除有效预约与本轮已选项占用后，取第一段长度足够的共同空闲区间的起点；全部资源必须**同时**连续可用，不能拼接空隙。
- 全部资源可用才选中；**受阻项继续等待，随后继续检查后项**——例如 W0001 受阻而 W0002 可行时，W0002 本轮兑现，绝不为增加兑现数量而重排队列或让后者顶掉、移动前者。
- 每个选中项各生成一项**普通预约**（`B…`，不加入系列、不改动任何原预约）；新预约、候补的已兑现状态及对应预约标识**一并原子保存后才报告成功**。
- 结果按队列顺序展示：选中项给出候补标识与预约标识、实际时间和完整资源（弹性项另附原窗口与时长）。等待项中，**弹性项按最终安排列出窗口内全部最大共同空闲区间及分钟数**（按开始时间排序，空集明确提示）；**固定项列出开放不足资源与全部阻挡**（含本轮后项产生的预约）。
- **没有可兑现项也成功**：明确说明，且不改变任何记录、占用或标识计数。
- `list-waitlist` 按登记顺序显示全部候补的标识、种类与两种原请求（固定时段，或弹性窗口+时长）、资源、等待/已兑现/已取消状态及兑现后的预约标识（含其当前实际时间）；空队列明确提示。
- `cancel-waitlist` 只能取消等待项（固定或弹性均可），记录保留；重复取消已取消项成功且不变；未知标识或取消**已兑现**项失败。
- 兑现后的预约就是普通预约，可用 `reschedule-booking`/`reschedule-batch`/`cancel-booking` 处理；候补始终保留原请求与关联、**不恢复等待**。重复执行 `process-waitlist` 不会为已兑现或已取消项再次创建预约。
- 重启后队列顺序、状态与关联仍在。候补状态、种类或关联非法，时长缺失/非正整数/超过窗口长度，数据损坏、保存失败均明确拒绝，原文件、全部记录、占用与标识计数不变。

## 候选组合查询（find-slot）

`find-slot --window <开始/结束> --duration <分钟> --group <候选,逗号分隔> [--group ...]` 在营业地时间窗口内，为一组**有顺序的需求**寻找能同时满足全部需求的**最早连续时段**，方便在多个场地、设备或人员备选中安排一次预约。输入表示：每个 `--group` 列出一个需求组中可任选其一的已登记资源标识（逗号分隔），例如两名工作人员可由两个需求组表达。

- 至少一个 `--group`，每组非空；**组内重复或未知资源拒绝**（退出码 1）；同一资源允许出现在不同组（求解时保证所选互不相同）。时长为**不超过窗口长度的正整数分钟**；窗口使用 `YYYY-MM-DDTHH:mm/YYYY-MM-DDTHH:mm`（年份 `0001`–`9999`，真实有效、结束晚于开始、允许跨日、不随机器时区变化）。
- 每组**恰选一个**候选，全部所选资源**互不相同**，并在整个时段**保持同一组合**——不中途更换资源、不拼接间断时间。求解按整体可行性判断：不会因逐组贪选较小标识而漏掉需要调整前组选择的可行组合，也不会把每组各自可行误当成整体可行。
- 各资源空闲时间 = 开放区间合并重叠或相接后扣除**有效停用**并集，再扣除**当前有效预约**占用（普通预约、系列成员、导入预约与候补兑现预约均按当前安排占用；取消的预约/停用与未兑现候补不阻挡）。区间左闭右开，端点相接可行；全部选定资源须同时连续空闲，结束不得超出窗口。
- 有解时显示起止时间，并按需求组顺序显示各组所选资源的标识、名称和类型；**同一最早开始有多个组合时**，将资源标识字符串按组顺序组成序列，取**字典序最小**的可行序列（组内候选输入顺序不影响结果）。**无解明确提示且退出码为 0**，绝不返回少组或缩短时长的方案。
- 本命令**只读一份完整数据快照**：不等待或改动写入保护，不创建预约、候补或任何记录，不写数据文件或推进计数。方案**不保留位置**，后续创建预约仍检查最新状态。

## 联合排程（schedule-flex）

`schedule-flex <预约清单文件>` 读取本地 UTF-8 JSON 清单，为**整份清单**的多项弹性预约寻找**同时可行**的安排，并**原子创建**全部预约。适合一次安排多场时间、资源都可浮动的活动。顶层为 `{"items": [...], "relations": [...]}`，清单非空且有顺序；每项给出时间窗口、连续分钟数与有顺序的需求组；`relations` 可省略或为空数组（省略或为空保持无关系的原行为）：

```json
{
  "items": [
    {"window": "2026-10-12T08:00/2026-10-12T18:00", "duration": 60, "groups": [["R0001", "R0002"], ["R0003"]]},
    {"window": "2026-10-12T09:00/2026-10-12T12:00", "duration": 90, "groups": [["R0001"]]}
  ],
  "relations": [
    {"predecessor": 1, "successor": 2, "minGap": 0, "maxGap": 120}
  ]
}
```

清单规则：

- 每项字段：`window`（`YYYY-MM-DDTHH:mm/YYYY-MM-DDTHH:mm`，年份 `0001`–`9999`，真实有效、结束晚于开始、允许跨日、与机器时区无关）、`duration`（**不超过窗口长度的正整数分钟**）、`groups`（有顺序的需求组数组，每组是一个候选资源标识数组）。
- **至少一组、每组非空**；未知或组内重复资源整单拒绝（退出码 1）；资源可跨组、跨项出现，但**一项所选资源须互不相同**。存在未知字段、清单不可读或损坏同样整单失败。
- 每项须**完整落在自身窗口内**：每组恰选一个候选，全部所选资源**同时连续可用且全程固定**（不中途更换资源、不拼接间断时间）。开放区间重叠或相接先合并，再扣除**有效停用**及全部**有效预约的当前占用**；取消的预约/停用与未兑现候补不阻挡。新项之间仅**共同资源的左闭右开时间重叠**才冲突，端点相接可行。

项间关系（顶层 `relations`，附加、可省略或为空）：

- 每条关系以**从 1 开始的清单序号**指定前项 `predecessor` 与后项 `successor`，并给出非负整数分钟的最小、最大衔接间隔 `minGap`/`maxGap`（**`minGap ≤ maxGap`**）。语义为 **后项开始 − 前项结束 ∈ [`minGap`, `maxGap`]**，含两端；两个值都为零时允许紧接（后项开始恰为前项结束）。
- 一项可有多个前项或多个后项，**全部关系同时生效**；关系方向**可逆清单顺序**（后项允许写在清单更前面），也适用于**不同资源**的项——关系只约束时间先后，不要求两项资源相关；关系的书写顺序不影响结果。
- **非整数或越界序号、自指（前项与后项同项）、重复有向关系（同一“前项→后项”写两次）、有向环均整单拒绝**（退出码 1）；两个相反方向的关系构成有向环。

求解与取舍：

- 必须找到**整份清单同时可行**的方案：不会逐项固定最早选择后漏掉须调整前项时间或资源的解，也不会跳过受阻项或返回部分方案。**最大间隔可能迫使前项延后**（后项只能较晚开始时，前项随之推迟以落在最大间隔内）；多个前项、逆清单方向与跨日关系同样纳入整单求解，既有时间、跨日与时区规则不变。
- 多个完整方案按**清单顺序**逐项比较：先比该项**开始分钟**，再按需求组顺序以**字符串字典序**比资源标识，第一处差异取较小者，随后才比较下一项。**候选书写顺序不影响结果**，**关系不改变取舍次序**；清单顺序只用于取舍，不限定活动发生的先后。

落盘与结果：

- 有解时按清单顺序各创建一项**普通预约**（稳定、不复用标识 `B0001`…，**不加入系列**、不改动既有预约或候补、**不自动处理候补**），**原子保存全部预约后**才退出 0，并显示各项标识、起止时间与按组对应的资源。重启后可查询，各项可独立改期或取消。**关系只在创建时约束求解**：预约记录上不保留关系，随后各项仍可独立改期或取消。**每次提交都是新的创建请求**，不按清单路径或内容去重。
- **无整体解明确提示并退出 1**，不保存部分方案；非法输入（含非法关系）、读取失败、损坏数据、保护竞争或保存失败均退出 1 并说明原因，用法错误退出 2。失败不产生本次记录、占用或计数变化，取得保护后的读取、校验或保存失败保持数据文件原样。

## 使用统计（usage-stats）

`usage-stats --window <开始/结束> [--resource <标识> ...]` 统计窗口内所选资源的实际使用情况，帮助判断场地、设备、人员的繁忙程度。未指定 `--resource` 时统计**全部已登记资源**（名册为空时明确提示并退出 0）；**未知或重复资源拒绝**（退出码 1）。窗口使用 `YYYY-MM-DDTHH:mm/YYYY-MM-DDTHH:mm`（年份 `0001`–`9999`，真实有效、结束晚于开始、允许跨日、与机器时区无关），窗口及所有区间**左闭右开**。

- 每个资源的**实际可用时间** = 开放区间合并重叠或相接后扣除**有效停用**并集，再裁剪到窗口。**占用**只计有效预约的**当前时间与当前资源**（普通预约、系列成员、导入预约与候补兑现预约同口径；已取消预约/停用、未兑现候补、导入首次请求快照与改期历史快照均不计），并取与实际可用区间的交集；同一资源的重叠占用合并，**一分钟只计一次**；多资源预约在每个所选资源分别计时。
- **逐日明细**覆盖与窗口有正长度交集的全部营业日期（按午夜拆分，首尾不足一天只计窗口内部分），包含零可用或零占用的所选资源，按日期再按资源标识字符串排序；每行显示资源标识、名称、类型与可用、占用、空闲分钟及使用率。**空闲 = 可用 − 占用**；**使用率 = 占用 ÷ 可用**，百分比四舍五入至两位小数，分母为零显示**不适用**。
- **整窗汇总**先按资源逐行给出整窗的可用、占用、空闲分钟与使用率，再合计全部所选资源的可用、占用、空闲**资源分钟**与使用率——合计以**总占用 ÷ 总可用**计算，不平均各项百分比。
- **繁忙峰值**：窗口内同时被占用的所选资源数量峰值，以及全部达到峰值的**最大连续区间**（按开始时间排序）。按**资源**而非预约计数；端点交接（一段结束、另一段同时开始）不制造瞬时重叠，相接的峰值段合并；无占用时峰值为零且不列区间。
- 本命令**只读一份完整数据快照**：不等待或改动写入保护，不创建任何记录，不写数据文件或推进计数；成功退出 0，非法请求、读取失败或损坏数据退出 1 并说明原因，用法错误退出 2。

## 停用规则

`add-closure` 为一个已登记资源登记一段**临时停用**（场地维护、设备检修、人员休息），`cancel-closure` 使其失效。

- 登记指定**一个**已登记资源及起止时间，**不要求该区间原本开放**。时间使用 `YYYY-MM-DDTHH:mm`（年份 `0001`–`9999`，真实有效、结束晚于开始、允许跨日、不随机器时区变化）。
- **不附清单**时，登记前检查该资源的**全部有效预约**（含系列成员与候补兑现预约；已取消不阻挡；区间左闭右开，端点相接不算重叠）：有时间重叠即拒绝，列出全部受影响预约标识及时间，**不改期或取消它们**。
- **附本地弹性改期清单**（`add-closure ... <清单文件>`，可选的位置参数）时，一次提交停用与替代安排，清单的格式、字段与输入校验**完全沿用 `reschedule-flex`**（见“弹性批量改期（reschedule-flex）”）：顶层 `{"items": [...]}`，非空有序，每项给出 `bookingId`、`window`、有顺序的候选资源组 `groups`，**时长保持预约当前值**；未知、重复或已取消预约整单拒绝，普通预约、系列成员、导入预约与候补兑现预约可混合。
  - 与**拟停用共同资源时间重叠的全部有效预约**（左闭右开）都必须纳入清单；清单还可**额外纳入为腾挪而调整的预约**。漏项一次性**列出全部遗漏标识及时间并拒绝**。
  - 求解**停用生效后的整单安排**：各资源开放合并重叠或相接后扣除其**有效停用并集**，**拟停用也计入**（即使该区间原本不开放），再**排除本批旧占用**；其余有效预约阻挡，取消记录与未兑现候补不阻挡。各项**完整落窗**，每组恰选一个互异资源，全部资源**同时连续可用且全程固定**；本批之间仅共同资源的左闭右开时间重叠才冲突，端点相接可行。
  - 取舍同 `reschedule-flex`：**先最少变化预约数量**（时间或完整资源集合不同才算变化，资源顺序不计），数量相同再按**清单顺序**先比开始分钟、再按组序比资源标识字符串，取最小完整方案；候选书写顺序不影响结果。
  - **停用、改期及有变化时的一条现有批量操作记录同次原子保存后才退出 0**，显示停用标识、各项时间与按组资源，有变化另示操作标识。**每次成功登记都创建新停用**（停用计数每次成功登记都推进）；改期**无变化时不建操作记录、不推进操作计数**。记录按清单顺序含全部提交项的前后安排及系列归属，与 `reschedule-batch`/`reschedule-flex` 同表，可用 `list-batch-ops` 查询、`undo-batch-op` 整笔安全撤销。
  - **只改本批预约的时间与资源**：标识、状态、系列归属、导入首次身份及候补原请求与关联全部保留，不新建预约、**不自动处理候补**。
  - 无整体解、漏项、非法输入、清单不可读/损坏、读取或保存失败、锁竞争均退出 1；失败不留本次停用、改期、记录或计数变化。用法错误退出 2。
- 返回稳定且不复用的停用标识 `C0001`…；**相同内容再次登记也是另一记录**，允许停用重叠或相接。
- 资源的**实际可用时间** = 原开放区间合并后扣除全部有效停用区间的并集（原开放记录保留）。创建预约、单项及批量改期、创建系列、登记及处理候补均按实际可用时间检查全部资源的完整覆盖；停用导致不足时列出受影响资源及相关有效停用标识和时间。
- 已有候补不因新增停用而删除、取消或被判作损坏数据；处理时受阻项继续等待并检查后项，保留登记顺序。取消停用后候补仅在再次手动 `process-waitlist` 时尝试兑现，已兑现关联不变且不恢复等待。
- `cancel-closure` 仅使指定记录失效并保留历史；重复取消成功且无变化，未知标识失败。其他重叠停用仍有效，恢复范围不超出原开放时间；**取消停用不自动恢复预约**、不自动创建预约或处理候补。**安全撤销仅恢复改期，不取消停用**：`undo-batch-op` 仍要求全部涉及预约有效且当前安排与记录改期后安排一致；恢复目标的原安排仍被（尚未取消的）停用阻挡时**整笔拒绝**，先 `cancel-closure` 解除阻挡且全部预约仍有效、与记录后安排一致后，整笔恢复才可行。
- `list-closures` 按开始时间、标识列出全部记录的资源、时间与有效/已取消状态；空结果明确提示。

## iCalendar 导入

`import-ical <iCalendar 文件> --resource <标识> [--resource <标识> ...]` 读取本地 UTF-8 的 iCalendar 文件，全部新事件统一使用命令行给定的资源集合（至少一个**不同的已登记资源**）：无 `RRULE` 的独立事件创建一项**普通预约**（不自动处理候补）；带按周重复规则的事件创建一个**预约系列**，仅为未排除的发生生成成员。同一 UID 的按周主事件可配若干**单次改期例外 VEVENT**（见下）。简短文件示例（另见 `examples/events.ics`）：

```
BEGIN:VCALENDAR
VERSION:2.0
BEGIN:VEVENT
UID:meeting-001@example.com
DTSTART:20261012T100000
DTEND:20261012T110000
END:VEVENT
BEGIN:VEVENT
UID:weekly-review@example.com
DTSTART:20261006T100000
DTEND:20261006T110000
RRULE:FREQ=WEEKLY;COUNT=4
EXDATE:20261013T100000
END:VEVENT
BEGIN:VEVENT
UID:weekly-review@example.com
RECURRENCE-ID:20261020T100000
DTSTART:20261021T140000
DTEND:20261021T150000
END:VEVENT
END:VCALENDAR
```

文件规则：

- 顶层为 `VERSION:2.0` 的 `VCALENDAR`，至少含一个 **VEVENT**；每项须有一个**非空 UID、DTSTART 和 DTEND**。
- 时间仅支持**浮动的 `YYYYMMDDTHHmmss`**：秒为 `00`，年份 `0001`–`9999`，真实有效、结束晚于开始、允许跨日、不随机器时区变化。
- 支持 **CRLF 或 LF** 行尾、**标准折行**（续行以空格或制表符开头）与 **UID 文本转义**（`\\`、`\,`、`\;`、`\n`）；属性名忽略大小写，**解码后 UID 区分大小写**。
- 描述属性（`DESCRIPTION`）忽略；**全天**（`VALUE=DATE`）、**时区**（`TZID`、UTC 写法）、**取消事件**（`STATUS:CANCELLED` 或 `METHOD:CANCEL`）及**事件内嵌套组件**（如 `VALARM`）一律拒绝；结构错误、关键属性（UID/DTSTART/DTEND）重复均**整批失败**。
- 重复规则**仅支持 `RRULE:FREQ=WEEKLY;COUNT=n`**：`COUNT` 为 `1`–`100000` 的整数且**含首项**，部件名大小写与先后顺序无关；其余 `FREQ`（DAILY 等）与 `INTERVAL`/`BYDAY`/`UNTIL` 等任何其他部件、重复 RRULE 均整批拒绝。`RDATE`、`EXRULE` 等其他重复属性仍一律拒绝。
- 首项由 `DTSTART`/`DTEND` 确定，每项起止时间**同时后移 7 个营业地日历日**，时刻与跨日长度保持不变；任一项（含其跨日结束）展开越出 `0001`–`9999` 年范围即整批拒绝。
- **EXDATE** 沿用浮动时间及参数限制（全天、TZID 等同样拒绝），支持**多行 EXDATE 与逗号分隔列表**，所有时间按**集合去重**；EXDATE **只能匹配某一发生的原开始时间**（时刻须一致），排除成员、排除首项均允许。**无 RRULE 却有 EXDATE、全部发生都被排除**均整批拒绝。

单次改期例外（RECURRENCE-ID）：

- 允许**同一 UID 的一个按周主事件配若干例外 VEVENT**：主事件即不带 `RECURRENCE-ID` 且带按周 `RRULE` 的那个 VEVENT，**必须随文件提交**；例外 VEVENT 各带**恰好一个** `RECURRENCE-ID`，在文件中位于主事件之前或之后均可。两个同 UID 的主事件、独立事件（无 RRULE）配例外、例外缺少主事件，以及**其余任何重复 UID** 均整批拒绝。
- 例外须有**单个** `RECURRENCE-ID` 及自身 `DTSTART`/`DTEND`：三种时间均沿用浮动 `YYYYMMDDTHHmmss`、秒 `00`、年份 `0001`–`9999`、结束晚于开始、允许跨日等同一套参数限制；`RECURRENCE-ID` **不得带 `RANGE` 参数**、不接受逗号列表，全天/TZID/UTC 写法同样拒绝。
- `RECURRENCE-ID` 必须**匹配主事件按 RRULE 展开后某个未排除（未被 EXDATE 排除）发生的原开始时间**（时刻须一致）；**同一原发生不得有两个例外**。例外可改时间**与时长**，但仍属该系列并使用命令行资源；例外 VEVENT **不得带 `RRULE`、`EXDATE`**。
- 展开沿用主事件的 RRULE 与 EXDATE 规则：展开并排除后，用例外的 `DTSTART`/`DTEND` **替换**对应原发生的目标时段——**不额外生成成员**，被替换的原时段已释放，**不参与覆盖或冲突校验**。
- 文件可混合独立事件、多个系列（各自可带例外）、新项与重放项。

身份与重放：

- UID 在同一数据文件中**永久关联首次请求**，身份不依赖导入文件路径：独立事件关联其首次生成的预约；重复事件关联首次创建的**系列**、每个**原发生时间**及其对应的成员预约，并持久保留首项时间、COUNT、排除集合、**按原发生关联的例外起止时间集合**（`RECURRENCE-ID` → 例外 `DTSTART`/`DTEND`）与资源集合。
- 相同 UID 的**重复与否、首项时间、COUNT、排除集合、例外集合或资源集合**任一不同即**整批拒绝**，绝不覆盖本地安排；RRULE 部件、排除值与**例外的书写顺序**、重复书写的排除值、命令行资源的顺序不算变化——已关联 UID **新增、删除例外或改变任一例外时间**都整批拒绝，例外书写顺序不影响身份。
- 请求一致为**重放**：独立事件返回原预约的当前安排与状态；重复事件按原发生顺序列出原系列、每个原发生时间、对应预约及其**当前**时间、资源、状态（首次请求带例外的发生另附首次导入时的例外目标作关联说明）——成员被单独改期、单独取消、随批量改期安全撤销或被整体取消系列后，重放**不覆盖、不复活、不重建、不补员**。
- 文件可**混合独立与重复事件、新项与重放项**：仅新目标接受校验，重放成员按其**当前有效**安排参与占用（已取消不占用）。

校验与落盘：

- 新目标（独立事件 1 项；重复事件为全部未排除发生套用例外替换后的最终时段）须被全部资源的连续**实际可用时间**（开放合并后扣除有效停用并集）完整覆盖；检查批内及全部既有有效预约（含重放成员的当前安排），只有共同资源的左闭右开区间重叠才冲突。
- 受阻时**按主事件或独立事件的文件顺序、再按事件内原发生顺序**报告全部受阻项的 UID、发生序号、**原发生与目标时间**、不足资源及相关停用标识和时间、全部冲突与共同资源；批内冲突在双方项中互列 UID、原发生与目标时间。
- 新系列、成员预约与导入身份（含例外快照）**一次原子保存**后才成功，按上述顺序显示新增或重放、完整关联与安排；不自动处理候补；**全部为重放时不写文件、不推进计数**。
- 旧数据无需迁移（无 `imports` 字段的旧文件视为空；**旧重复导入记录无 `exceptions` 字段视为空例外集合**，各入口读写与重启均保留身份）；导入记录的快照、成员现状（被改期/取消）与首次请求不同**合法**，但首次请求非法（COUNT/排除/时间非法）、映射缺漏或重复（发生时间重复、成员重复或不属于该系列、系列成员与映射不一一对应）、系列或预约引用非法，以及**例外快照非法**（结构/字段非法、例外时间非法、`RECURRENCE-ID` 不匹配未排除原发生、同一原发生重复例外）均视为**数据损坏**。输入、读取、校验或保存失败保留原文件、全部记录、占用与计数。

## iCalendar 导出（已导入按周系列）

`export-ical <已解码 UID> --output <输出文件>` 选择一个此前经 `import-ical` 导入的**按周重复系列**，把保存了本地变更后的**当前安排**导出为本地 iCalendar 文件（UTF-8、CRLF）：

```sh
node app.ts export-ical weekly-review@example.com --output ./weekly-current.ics
```

- 只能按**已解码 UID** 选择**已导入的按周系列**；未知 UID、UID 关联的是独立事件（无 `RRULE` 的首次导入）一律拒绝（退出码 1，不产生输出）。UID 文本按导入时同一套规则转义输出（反斜杠、逗号、分号、换行）。
- 输出为 `VERSION:2.0` 的 `VCALENDAR`（含非空 `PRODID`）；每个 `VEVENT` 含与首次一致的 `UID` 与一个**合法 UTC 的 `DTSTAMP`**。预约时间一律用**浮动** `YYYYMMDDTHHmmss`（秒为 `00`，年份 `0001`–`9999`，跨日与时区无关规则不变）。
- **主事件**（排在最前）保留**首次** UID、首项 `DTSTART`/`DTEND` 与 `RRULE:FREQ=WEEKLY;COUNT=n`；`EXDATE` 为**首次排除集合与已取消成员原开始时间的去重并集**（按原发生升序，单行逗号列表）。
- 对每个**仍有效**成员，拿其当前安排与**原周展开**（首项时间按 7 个营业地日历日纯算术后移，资源取首次资源集合）比较：**相对原周展开的起止时间或完整资源集合有变化**时，输出同 UID 的**例外 `VEVENT`**——`RECURRENCE-ID` 固定为该成员的**原开始时间**，`DTSTART`/`DTEND` 取**当前值**；无变化不输出例外。**首次导入时携带的例外也按此规则重新比较**（成员被本地改回原周展开即不再输出例外），绝不照抄首次例外快照。已**取消**的成员不输出例外；**全部成员取消**时仍生成合法但无有效发生的日历（全部原发生都在 `EXDATE` 中）。
- 例外排在主事件之后，**按原发生时间升序**。主事件 `DESCRIPTION` 使用**首次资源集合**，例外 `DESCRIPTION` 使用该成员的**当前完整资源集合**；均逐行列出资源标识、名称与类型并按标识排序。
- 文本正确转义反斜杠、逗号、分号与换行；统一 **CRLF**；物理行不超过 **75 个 UTF-8 字节**（不计行尾，但计续行前导空格），折行不拆开任何 Unicode 字符。
- **只读一份完整快照**：不等待或改动写入保护（持锁期间可正常导出），不修改业务数据、身份、历史或计数，原有 UID 重放规则不变；**旧记录无 `exceptions` 字段仍可导出**（按空例外集合）。
- 完整输出先写临时文件再**原子替换**，替换成功后才退出 0，并报告**有效成员、排除与例外数量**。输出路径与**数据文件、写入保护文件或恢复协调文件**等价（含相对/绝对/`./..`、符号链接等价写法）时拒绝；非法请求、损坏数据、读写失败退出 1 并说明原因，**原输出文件与业务文件保持不变**；输出原本不存在时失败也不留下半成品。用法错误退出 2。

## 数据与退出码

- 已有数据文件**无需手工迁移**：旧文件（无 `series`、`waitlist`、`closures`、`batchOps`、`imports` 字段，或旧候补记录无 `kind`/弹性字段，或旧导入记录无系列身份字段，或旧资源记录无 `prepMinutes`/`teardownMinutes` 字段——缺字段一律按 `0`）可直接继续查询和修改，缺少候补、停用、批量改期或导入记录时视为空且不补造历史，旧候补记录一律按固定时段候补处理，旧导入记录一律按独立事件身份处理；旧重复导入记录无 `exceptions` 字段时按空例外集合处理；各旧入口读写均不会丢失候补、停用、批量改期操作记录及其撤销状态与导入身份。持久化的准备/整理字段若不是非负安全整数，视为结构非法（损坏），原样保留文件并拒绝加载。
- 资源、预约、系列、候补、停用与批量改期操作标识稳定且不复用（`R0001`…、`B0001`…、`S0001`…、`W0001`…、`C0001`…、`O0001`…）；撤销不回收也不推进操作计数。

- 数据文件不存在按空数据处理；**损坏或结构非法时直接失败并原样保留文件**（含候补状态、种类、时长或关联非法，批量改期记录的结构、引用或快照非法，以及导入记录的 UID 重复、预约或系列关联非法或重复、首次请求或发生映射非法、例外快照或关联非法）。修改先写临时文件再原子替换，校验或保存失败不会改动任何记录、占用、记录状态或标识计数。多进程并发修改由写入保护互斥（见“多进程写入保护”），进程异常退出后数据只会是提交前或提交后的完整快照，残留保护用 `recover-lock` 恢复。
- 改期清单不可读、损坏（非法 JSON）或内容非法时明确失败；批量改期校验或保存失败保留原数据文件及全部记录和计数，不留下部分改期、不留下操作记录。预约清单不可读、损坏或内容非法、整单无可行方案时同样明确失败，不创建任何预约、不推进标识计数，数据文件保持原样。弹性批量改期清单不可读、损坏或内容非法、整单无可行方案时同样明确失败，不改动任何预约、不留下操作记录、不推进计数。`add-closure` 附改期清单时，漏列重叠预约、清单非法、停用生效后整单无可行方案或保存失败，都不留下本次停用、改期、操作记录或停用/操作计数变化（停用与改期、记录本就同一次原子保存，三者要么全有要么全无）。撤销校验或保存失败时原文件、全部安排、记录状态和计数不变。iCalendar 文件不可读、结构非法（含重复规则或部件非法、无规则带 EXDATE、全部排除、展开越出年份、例外 VEVENT 缺主事件/配错主事件/带 RRULE/EXDATE/RANGE、RECURRENCE-ID 重复或不匹配未排除原发生）、UID 与首次导入不一致（含例外集合增删改）或新目标受阻时整批失败，原文件、全部记录及计数不变。
- 无参数、`-h`、`--help` 显示帮助；各入口拒绝未知选项与多余位置参数。
- 退出码：`0` 成功（含候选组合查询无解的明确提示、统计名册为空的明确提示）；`1` 业务失败（空名称、未知/重复资源、需求组为空或含未知/组内重复候选、非法时间或次数、开放不足、冲突、超出四位年份、未知系列、未知候补、取消已兑现候补、未知批量改期操作、撤销涉及预约与记录不一致或恢复安排受阻、预约清单不可读/损坏/内容非法（含项间关系序号越界、自指、重复有向关系、有向环、间隔非法）或整单无可行方案、弹性批量改期清单不可读/损坏/内容非法或整单无可行方案、**停用与有效预约重叠（不附清单）、停用同次改期清单不可读/损坏/内容非法、漏列与拟停用重叠的有效预约、停用生效后整单无可行方案**、批量改期记录结构或快照非法、iCalendar 文件不可读/结构非法（含重复规则或部件非法、无规则带 EXDATE、全部排除、展开越出年份、RECURRENCE-ID 例外缺主事件或主事件非按周系列、例外带 RRULE/EXDATE/RANGE、RECURRENCE-ID 重复或不匹配未排除原发生）、UID 与首次导入不一致（含例外增删改）、新事件开放不足或冲突、iCalendar 导出遇到未知 UID 或 UID 关联独立事件、输出路径与数据/写入保护/恢复协调文件等价、导出读写失败、数据损坏、数据文件被其他进程占用或恢复被拒绝等，附带原因）；`2` 用法错误（未知参数、缺少选项、多余位置参数）。附清单的停用提交在取得保护后的读取、校验、求解或保存失败时，不留本次停用、改期、操作记录或计数变化，持锁失败保持原文件，不回退其他请求已提交的内容。

## 维护说明

- 多项预约目标的可行性校验只有一套：`validateBatchTargets`（app.ts“业务校验”段），创建系列、批量改期、安全撤销与 iCalendar 导入共用，不再在各入口重复整批可行性循环。它针对**全部目标生效后**的安排统一检查：实际可用覆盖（开放区间重叠或相接合并后扣除有效停用并集，须连续覆盖目标）、批外有效预约占用（已取消不占用）、批内目标间冲突；区间左闭右开、端点相接可行、仅共同资源重叠算冲突；一次性收集全部失败项，批内冲突在双方失败项中都出现。
- 该函数**只读**：不修改目标、业务记录或标识计数；输出渲染与落盘提交仍由各入口负责（完整保存后才报告成功，失败保留原文件、安排、历史状态与全部计数）。
- 各入口只负责三件事：把业务目标展开为 `ValidationTarget` 数组（系列=展开后的全部成员；改期=各提交项目标；撤销=各项恢复安排；导入=新独立事件自身及新重复事件全部未排除发生套用 RECURRENCE-ID 例外替换后的最终目标，按主事件/独立事件文件顺序与原发生顺序展平，例外被替换原时段不进目标即不参与覆盖或冲突，重放成员按当前安排和状态参与既有占用，不用首次导入快照代替现状）；给出需排除当前占用的预约标识集合（改期与撤销排除本批涉及预约以允许整批交换，系列与导入传空集合）；按各自业务定位与顺序渲染诊断（系列按发生顺序及成员时间，改期与撤销按提交顺序及预约标识，导入按文件及原发生顺序及 UID、原发生与目标时间；系列内部冲突以双方时间定位，其他批内冲突列对方标识及目标时间，导入批内冲突互列 UID、原发生与目标时间）。
- UID 一致性、撤销的有效状态与当前值匹配、重复撤销判定仍由各入口处理，不进入共享校验；请求身份与预约身份不混淆。
- 修改校验规则只改 `validateBatchTargets` 及其依赖（`findCoverageGaps`/`findConflicts`/`availableSegmentsOf`）；新增多项目标入口时复用该函数，不要在入口内另写整批可行性循环。
- 多进程写入保护只有一套：`acquireWriteLock`/`releaseWriteLock`（app.ts“多进程写入保护”段）。修改入口一律经 `loadStoreForWrite` 读取数据（先取锁再读最新状态），锁由 `main` 的 `finally` 统一释放；查询入口继续用 `loadStore`，不取锁。新增修改入口时同样走 `loadStoreForWrite`，不要绕过锁直接 `loadStore` 后写文件。锁文件按数据文件规范路径命名（`lockPathFor`，等价路径共享）；`recover-lock` 是唯一恢复入口，只在确认原写入进程已退出后删锁。恢复者之间以恢复协调文件（`recoveryPathFor`，wx 独占创建）互斥，在互斥内重新核对目标后才删除锁文件——不要改成“再读一次比对后删除”之类的非原子做法；恢复者异常退出留下的残留协调文件由后续恢复入口确认其持有者退出后清理。
- `find-slot` 是纯查询：只经 `loadStore` 读一份快照，不取锁、不写文件、不推进计数。空闲区间按**活动坐标**计算：`resourceActivityAvailableSegments` 把实际可用段 `[a,b)` 化为 `[a+准备,b−整理)` 并裁进窗口（窗口只限制活动起止），`resourceActivityFreeSegments` 再扣除当前有效预约按各资源自身缓冲扩张的活动坐标阻挡 `[bs−(准备+整理), be+(准备+整理))`；组合搜索在“候选资源空闲段起点”集合上逐一升序试探（最早可行开始必为某段空闲起点），固定开始分钟上的字典序最小组合由 `lexMinAssignment` 逐组试探并以增广路匹配保证剩余组整体可行——不要改成逐组各自贪选最小标识的贪心。
- 准备/整理缓冲的唯一口径是 `occupancyOnResource(r, s, e) = [s−准备_r, e+整理_r)`（每资源分别扩张，绝不取最大缓冲）：覆盖校验经 `findCoverageGaps`（另用 `MIN_MINUTE`/`MAX_MINUTE_EXCL` 拒绝越出 0001–9999 年的实际占用），冲突经 `findConflicts` 返回逐共同资源的双方实际占用，批内冲突在 `validateBatchTargets` 内同口径判定，诊断统一经 `gapLines`/`renderConflictLines` 渲染（冲突须列全部预约、共同资源及双方占用起止）。`usage-stats` 的占用计时、`add-closure` 的受影响识别都用同一函数（停用区间自身不扩张）；不要在入口另写按活动时间重叠的判断。
- `schedule-flex` 是修改入口：经 `loadStoreForWrite` 取得写入保护后读最新数据，排程至保存全程受保护。求解器 `solveFlexPlan` 的关键不变式：最小方案的每个项开始分钟，要么是自身窗口内某段基础空闲的起点，要么被另一新项在共同资源上的实际占用结束“顶住”（共同资源 r 的准备+整理为 `buf_r` 时 `s_i = s_j + d_j + buf_r`，逐共同候选资源传播，不取统一最大缓冲），要么落在某项间关系的间隔边界上（关系 `p -> q` 间隔 `[lo,hi]`：已知 `s_p` 传播 `s_q = s_p+d_p+lo`、`s_p+d_p+hi`；已知 `s_q` 传播 `s_p = s_q-d_p-hi`、`s_q-d_p-lo`；逆清单方向与不同资源的项同样传播）——候选开始分钟取这三类的闭包（资源冲突仅在候选资源集合有交集的项之间传播），随后按清单顺序深度优先试探（开始升序、同一开始的资源序列由 `assignmentsInLexOrder` 按字典序升序枚举），放置每项时对两端都已放置的关系检查 `minGap ≤ s_后 − e_前 ≤ maxGap`（每条边恰在第二个端点放置时检查一次，逆清单方向由前项放置处补查），首个完整方案即“逐项先比开始分钟、再按组序比资源标识”的最小方案。关系清单由 `parseFlexRelations` 校验（越界/非整数序号、自指、重复有向关系整单拒绝，Kahn 拓扑排序拒绝有向环），省略或为空关系时走原路径。不要改成逐项固定最早选择的贪心（会漏掉须调整前项时间或资源、或被最大间隔顶推延后的解），也不要跳过受阻项。有解时按清单顺序分配预约标识并一次原子保存；无解或任何失败不落盘、不推进计数。关系只用于创建时求解，不写入预约记录。
- `reschedule-flex` 同为修改入口（`loadStoreForWrite` 全程受保护）。求解器 `solveFlexReschedule` 复用上述闭包不变式，但候选开始分钟额外纳入**各项当前开始**（在窗内时，“保持现状”是合法候选），并按变化数 `k = 0..n` 递增做带预算的深度优先试探（起止时间或完整资源集合不同才算变化，资源顺序不计；不变项同样放置以阻挡他项）：首个有解的 `k` 即最少变化数，该预算下首个完整方案即“逐项先比开始分钟、再按组序比资源标识”的最小方案。本批预约的旧占用经 `resourceActivityFreeSegments` 的排除参数不计为障碍，其余有效预约按现状阻挡。只改时间与资源；有变化时把全部提交项的前后安排记为一条 `BatchOpRec`（与 `reschedule-batch` 的记录、查询、撤销完全同构，不要另建记录类型），与改期同次原子保存；无变化成功不写文件、不建记录、不推进计数。
- `add-closure` 的可选清单路径**不另写清单解析与求解器**：清单位置参数直接复用 `loadManifest`/`parseFlexRescheduleShape`/`parseFlexRescheduleItems`（报错文案与退出码与 `reschedule-flex` 完全一致），求解复用 `solveFlexReschedule` 的第三参数 `extraCutsById`——把拟停用 `[startMin,endMin)` 作为其资源的附加扣除传入（经 `resourceActivityFreeSegments` → `availableSegmentsOf` 的 `extraCuts` 与既有有效停用合并扣除；注意该区间是停用自身的区间，停用不做缓冲扩张），拟停用因此在未落盘时即计入覆盖与冲突。附清单前先做**漏项检查**：与拟停用共同资源时间重叠的全部有效预约必须在清单内（清单可额外含腾挪所需预约），漏项一次性列全拒绝。停用每次成功都新建（`closureSeq` 必推进）；是否建 `BatchOpRec`、是否推进 `batchSeq` 只取决于改期是否有变化；停用、改期、记录在**同一次 `saveStore`** 落盘，任何前置失败都不产生三者之一。`undo-batch-op` 无需特殊分支：撤销只读当前 store 做恢复可行性校验，仍有效的停用自然阻挡原安排（整笔拒绝），`cancel-closure` 解除后即可整笔恢复——不要在撤销里自动取消停用。
- `usage-stats` 同样是纯查询：只经 `loadStore` 读一份快照，不取锁、不写文件、不推进计数。实际可用区间复用 `availableSegmentsOf`/`clipSegments`；占用由 `occupiedSegmentsOf` 取有效预约当前时间与当前资源、裁剪进窗口后与实际可用区间求交并合并（一分钟只计一次）；逐日拆分按营业地日历日序号（`分钟数 ÷ 1440` 向下取整）切分，不依赖机器时区；峰值由 `peakConcurrency` 对全部所选资源的占用区间做扫描线计数（同一时刻的端点变化合并结算，端点交接不制造瞬时重叠，相接峰值段自然合并）。新增统计口径时沿用这些区间原语，不要另写一套。
- `export-ical` 也是纯查询入口：只经 `loadStore` 读一份快照，不取锁、不等待保护、不写数据文件或推进计数；只写 `--output` 指定的输出文件（先写 `<输出>.<pid>.tmp` 再原子改名，失败清理临时文件且不动原输出）。例外判定只有一个口径：成员**当前**起止与完整资源集合对比“首项时间按 7 个营业地日历日纯展开 + 首次资源集合”的原周安排——绝不使用 `ImportRec.exceptions` 首次例外快照代替比较（该快照只用于 UID 重放身份）；EXDATE 永远是首次排除集合与已取消成员原开始的并集。文本经 `escapeIcalText` 转义、`foldIcalLine` 按 UTF-8 字节（码点粒度）折行，统一 CRLF、物理行 ≤75 字节；输出前用 `canonicalDataPath` 拒绝与数据文件、锁文件（`lockPathFor`）、恢复协调文件（`recoveryPathFor`）等价的路径。新增导出字段时沿用这几处原语，不要在命令里另写折行或路径比较。
- 测试同步点（`testSyncPoint`，仅当环境变量 `SHIFTBOOK_TEST_SYNC_DIR` 指向某目录时启用）是回归测试专用钩子：在“取得写入保护后”“恢复删除锁前”两个交接点写 `<目录>/<名>.ready` 并等待 `<目录>/<名>.go`，让测试用真实子进程精确控制交错时序（明确同步点，而非随机延时）；正常使用不设置该变量，完全无开销。
